2. การเชื่อมกับงานหน้าเว็บ
#13: หน้ารายการ ค้นหา และกรองภาระงาน
#14: หน้ารายละเอียดภาระงาน พร้อมเปิดดู/ดาวน์โหลดหลักฐาน
หน้าเว็บเหล่านี้ต้องเชื่อมกับ API; การทำ #12 ไม่ได้ทำให้หน้าเว็บเดิมเปลี่ยนเอง
#14 ได้รับมอบหมายให้ทำต่อ แต่ยังไม่ได้พัฒนาในงานชุดนี้

ลำดับการทำงาน: หน้าเว็บ → FastAPI → Supabase → ส่งข้อมูลกลับไปแสดงบนหน้าเว็บ
ประโยชน์คือรวมกฎการค้นหาและสรุปไว้ที่เดียวให้หลายหน้าใช้ร่วมกัน
Supabase เรียกตรงได้เช่นกัน; FastAPI เป็นแนวทางที่ทีมเลือก ไม่ได้ปลอดภัยกว่าโดยอัตโนมัติ
สิทธิ์การอ่านยังขึ้นกับ Supabase/RLS ส่วนไฟล์ใน Public bucket ใครมีลิงก์ก็เปิดได้
ถ้าหน้าเว็บกับ API อยู่คนละ origin ต้องตั้งค่า CORS ให้ตรงก่อนเชื่อมใช้งาน

3. ทำไมมี .env สองที่
api/.env: สำหรับ FastAPI ใช้ SUPABASE_URL และ SUPABASE_KEY
pipeline/.env: สำหรับสคริปต์ดึงข้อมูล TU/OpenAlex ใช้ค่าของ pipeline ตามเดิม
หน้าเว็บ #14 ไม่ต้องสร้าง .env เพิ่มตามแนวทางนี้ และไม่ต้องรัน pipeline ทุกครั้ง

.env เป็นค่าจริงในเครื่อง ไม่ได้ push ขึ้น Git
.env.example เป็นไฟล์ตัวอย่าง ไม่ได้มีค่าจริงของเพื่อนให้โดยอัตโนมัติ
คัดลอกเฉพาะครั้งแรกที่ยังไม่มี .env แล้วเติมค่าที่แชร์ให้แยกต่างหาก
หากมี .env อยู่แล้ว ห้ามคัดลอกทับโดยไม่ตรวจสอบ เพราะค่าที่ตั้งไว้อาจหาย
ถ้ามีตัวแปรใหม่ ให้เพิ่มหรือแก้เฉพาะตัวแปรนั้นในไฟล์เดิม
อย่าใส่ service-role key ในหน้าเว็บ หรือส่ง secret key ลงกลุ่มทั่วไป

4. เริ่มใช้งานครั้งแรก (Windows / PowerShell)
เปิด terminal ที่โฟลเดอร์หลักของโปรเจกต์
ตรวจงานค้างในเครื่องก่อน pull; ถ้ามีให้ commit หรือ stash ตามเหมาะสม

git pull origin main

ถ้ายังไม่มี api/.env:
Copy-Item api/.env.example api/.env

เปิด api/.env แล้วเติม:
SUPABASE_URL=ค่าของโปรเจกต์
SUPABASE_KEY=publishable key ของโปรเจกต์

ถ้ายังไม่มี .venv ให้สร้างด้วย Python 3.10 ขึ้นไป:
python -m venv .venv

ติดตั้งไลบรารีครั้งแรก และติดตั้งซ้ำเมื่อ requirements เปลี่ยน:
.\.venv\Scripts\python.exe -m pip install -r api/requirements.txt

5. เปิด API ระหว่างพัฒนา
รันจากโฟลเดอร์หลักของโปรเจกต์:
.\.venv\Scripts\python.exe -m uvicorn api.main:app --reload

API: http://127.0.0.1:8000
หน้าเอกสารและทดลองเรียก API: http://127.0.0.1:8000/docs
127.0.0.1 หมายถึงเครื่องของคนที่เปิดใช้งาน แต่ละคนต้องเปิด API ในเครื่องตัวเอง
เว้นแต่ทีมจะกำหนด API server กลางไว้แล้ว

เปิด terminal ค้างไว้ขณะทดสอบหน้าเว็บที่เรียก API
เลิกใช้งานให้กด Ctrl + C เพื่อหยุด
ถ้าหยุด API หรือปิดเครื่องแล้ว กลับมาทดสอบครั้งต่อไปให้รันคำสั่งเปิด API ใหม่
ไม่ต้องสร้าง .venv หรือคัดลอก .env ใหม่ทุกครั้ง
เมื่อ deploy บน server แล้ว ผู้ใช้ทั่วไปไม่ต้องเปิด API เอง

หมายเหตุสำหรับเครื่องที่ทำ #12: ตั้ง api/.env, สร้าง .venv และติดตั้งไลบรารีไว้แล้ว
จึงรันคำสั่งเปิด API ได้เลย
